## 0. 诚实的样本量现实（决定本协议的主检验选择）

固定 N=10+10。功效核算（α=.05 双侧，power=.80）：
- 组间（专家 vs 普通人）：MDE d≈**1.32**（超大）；d=0.5 时功效仅 0.19，d=0.8 仅 0.40。
- 组内（20 对）：MDE dz≈**0.66**（中大，可行）。
- **人群×对照交互**：需约 4× 样本（≈每组 30–40）；N=20 **不足以** confirmatory 检验交互。

**结论（D-0127 诚实边界）：** 主 confirmatory 检验一律放在**组内**；**人群差异/交互降为 secondary/exploratory**，报效应量 + CI，明写 underpowered。不把 n=10/10 的交互当核心 Claim。

## 1. 研究问题与人群

「滑块好不好」人群相对：便利（写不出强 prompt 的人）vs. 有保证的增量控制（能写出强 prompt 的人）。average/best-prompt 两对照 = 两人群真实备选的操作化。

**人群划分（客观，非自报）——prompting proficiency：**
- 入组前做 **prompt-writing 探针**：给定标准化目标，参与者自己写一条 prompt；按预注册 rubric 客观评分（可加盲评双人一致性 κ）。
- **Proficient 层** = 探针分达预注册阈值（能写出接近 best-prompt 质量的指令）；**Non-proficient 层** = 未达阈值。
- 目标每层 10 人。广义 AI 熟练度（使用频率/调参/懂 latent 控制）**只作协变量问卷**，不定义组。
- 论文人群定义同步收紧为 "someone who can write a strong prompt for the task"。

> 待定（§8）：探针任务与 rubric 细则、阈值定法（预设 cutoff / 校准锚点）、是否双盲评分。

### 1.1 Prompt-writing 探针（草案 v0.2；供 owner/导师审）

**探针任务（标准化、与主任务同族但不同题）：** 给参与者一个书面目标 + 一段待处理素材（示意/虚构），要求**只用一条自然语言 prompt**（不许多轮、不许用滑块）让某助手产出满足目标的结果。目标含 3–4 个可核验的显性约束（如"限 X 字/包含 Y 要素/排除 Z/指定语气"）。参与者看不到评分标准。

**评分 rubric（解析式，0–6 分，预注册）：**
| 维度 | 0 | 1 | 2 |
|---|---|---|---|
| 约束覆盖（是否点到全部显性约束） | 缺≥2 | 缺 1 | 全覆盖 |
| 具体性/可执行（有无可操作的量化/示例/格式指令） | 空泛 | 部分 | 明确可执行 |
| 结构与无害（有无角色/步骤/边界，且无诱导有害/越权） | 无结构或有害 | 部分 | 良好且安全 |

**分层阈值（预注册，二选一，冻结前定死一种）：**
- **A. 固定 cutoff（推荐）**：≥4/6 = **proficient**；≤3/6 = **non-proficient**。用 2–3 个锚点样例校准评分者。
- **B. 样本内中位切分**：仅当固定 cutoff 导致某层招不满时作预注册回退，且明写为便利分层、削弱人群主张强度。

**评分流程：** 2 名评分者独立盲评（隐去分组/主任务表现），报 **Cohen's κ**；分歧第三人裁决。评分者不接触参与者主任务数据。

**协变量（不定义组）：** 广义 AI 熟练度问卷（使用频率 / 是否调过参数 / 是否理解 latent 控制 / 自评）。

## 2. 设计

**混合设计**：proficiency 层（between，2）× 对照条件（within）。
- 每位参与者在**匹配任务**上经历两/三种条件（顺序**抵消**）：
  1. **Slider 条件**：用 latent 滑块达成目标。
  2. **Own-prompt 条件**：自己写 prompt 达成同类目标（= 其真实备选；对 average-prompt 分布的每被试一次实现）。
  3. （可选）**Given-comparator 条件**：给定 best/average-prompt 产物作参照，桥接模型侧。
- 任务集配对、反事实平衡；条件与任务顺序用拉丁方/随机抵消。

## 3. 材料与任务集

### 3.0 工具架构：解耦式离线采集（D-0130，owner 选定方案一）

- **离线单文件 HTML 只采集,不跑模型**:采集参与者写的 prompt 文本、选的滑块设置、effort 埋点、问卷、探针、V3 门槛答案 → 导出 JSON(同 V3 分发→回收→汇总,零 API / 零数据库,绕开配额)。
- **无反馈回路 → 两条件一次性提交(对称公平)**:滑块条件与 own-prompt 条件均为**单次提交**,参与者当场**不看模型输出**;否则"滑块有反馈、prompt 无反馈"会混淆 H1 的质量对比。
- **Q 事后批量评分**:owner/Manager 把收集到的滑块设置 + prompt 批量喂模型,统一算 `Q(slider)` / `Q(own-prompt)`——作为**单独登记进 experiment-registry** 的评分实验(固定 code commit / seed / model / 方向 / rubric)。参与者端工具**不含任何模型输出或答案键**。
- **effort 语义**:当场测"一次性构造 effort"(时间/编辑次数/字数),**非迭代打磨 effort** → 写进 Limitations（§7）。

- **主任务（两轴测量用）= 新建独立开放生成任务集**：V3 材料是"理解/应用门槛"的判定题（封闭、有冻结正确答案），**不适合**做"用滑块 vs 写 prompt 拿更好结果"的开放生成对比。因此另起一个**独立、示意/虚构**的任务集（不污染 V3、不共用答案键）。
- **任务可双路完成**：每个主任务须能同时用「latent 滑块」与「自己写 prompt」两条路达成，且有可评 outcome（见 §4 quality rubric）。
- **配对与平衡**：任务集配对、反事实平衡；条件与任务顺序用拉丁方/随机抵消。
- **V3 门槛模块（H4，applicability）= 按引用嵌入**：直接调用 V3 冻结材料 v11.3 与离线判分做"可应用性诊断"，**逻辑指纹 / 答案 / 材料一字不改**。
- 全部材料标注 fictional/illustrative。

**建议任务规模（供 owner 审）：** 每条件 2–3 个配对主任务（控制单次时长 ≤ 45–60 min），外加 1 个 V3 门槛小节。

## 4. 测量（两轴；facet 名与论文对齐）

**便利轴：effort / accessibility / discoverability + willingness-to-use**
- Effort：客观（完成时间、操作步数、修改/迭代次数）+ 主观（简版 NASA-TLX / Likert）。
- Accessibility：无需自己 craft prompt 也能达成目标的完成率。
- Discoverability：能否看懂控件在做什么、怎么用。
- Willingness-to-use：滑块 vs 自己写 prompt 的选择与理由。

**有保证的增量控制轴（写作 session 已定：不塌进对象层 δ gate）**
- **主要 = 用户在环任务表现（+ effort / reliance）**：真实用户带自己 prompt + 滑块能否拿到更好结果 / 更省力 / 更校准依赖。
- **可选 secondary（桥接 0/12）**：同一 steer-vs-prompt 的对象层对比。
- **尺度警告：δ=0.05 是对象尺度 release bar，不照搬**；本协议按 power 预注册自己的 MDE（组内 dz）。

### 4.1 用户在环 quality 指标操作化（草案 v0.2）

- **任务结果质量 Q**：每个主任务产出由**预注册解析式 rubric** 打分（约束满足 / 事实正确 / 目标契合 / 无害），归一化到 0–100；同 §1.1 双评 + κ，评分者盲于条件（slider vs own-prompt）与分组。
- **每被试成对记录**：对每个配对任务，同时记 `Q(slider)` 与 `Q(own-prompt)`，构成组内配对差 `D_i`（见 §5）。
- **Effort（便利轴）**：客观（完成时间、操作/编辑步数、迭代次数，工具自动埋点）+ 主观（简版 TLX / Likert）。
- **Reliance / calibration（可选）**：参与者对自己产出质量的信心 vs 实测 Q 的校准偏差（over/under-reliance）。
- **盲评保证**：导出与评分材料剥离条件标签与答案键（同 V3：不进 payload/DOM/ARIA/export），评分阶段再对照。

> 判分/正确答案边界同 V3：任何正确答案/门槛判定只在 owner 端离线判分，绝不进参与者端 payload/DOM/ARIA/export。

## 5. 假设（中性、可证伪、无预设方向；主检验组内）

**主（confirmatory，组内，powered dz≈0.66）：**

- **H1（增量控制，proficient 层内）——真人版 release-bar。**
  对每个 proficient 参与者 *i*，在配对主任务上取组内配对差
  `D_i = Q(slider_i) − Q(own_prompt_i)`（Q = §4.1 归一化质量）。
  - 主检验：单侧配对检验 H0: `μ_D ≤ 0` vs H1: `μ_D > 0`。
  - **"有保证的增量控制"仅在**：`μ_D` 显著 > 0 **且** 95% CI 下界 ≥ 预注册用户尺度 MDE（δ_user，按 power 定，非照搬 0.05）**才判成立**——对象层 release-bar 的真人镜像。
  - 预测（非预设结论，仅记录方向假设）：不成立（滑块不显著赢过用户自己的 prompt）。
  - 报 `μ_D`、dz、95% CI、精确 p。

- **H2（便利，non-proficient 层内）。**
  对每个 non-proficient 参与者，取 effort 差
  `E_i = Effort(own_prompt_i) − Effort(slider_i)`（时间/步数/迭代，标准化）与 accessibility 完成率差。
  - 主检验：单侧配对检验 slider 是否更省力/可及（H0: 无差异）。
  - 报效应量 + 95% CI + p。

**次（exploratory，underpowered，仅报效应量+CI）：**
- **H3（人群×对照交互）**：H1/H2 效应是否随 proficiency 层不同（`D` 与 `E` 的层间差）。**明写 N=20 对交互 underpowered**，报效应量 + CI，不作 confirmatory 主张。
- **H4（可应用性，V3 门槛模块）**：两层应用对照约束门槛的正确率是否不同（V3 离线判分）。

## 6. 分析计划

- **主分析**：H1/H2 组内配对检验（或等价混合模型的组内对比）；报 dz + 95% CI + 精确 p。
- **次分析**：H3 交互项估计 + CI，标注 underpowered；H4 应用性描述 + CI。
- **协变量**：广义 AI 熟练度问卷、任务/条件顺序。
- **排除规则（预注册）**：注意力检查失败、探针无效作答、未完成、明显作弊/AI 代填等 → 预先写死。
- **随机化/seed**：条件与任务顺序随机的 seed 预注册；分层入组规则预注册。
- **多重比较**：主假设仅 H1/H2 两个，预注册校正法。
- **停止规则**：固定 N=20，不做数据依赖的加样（避免 optional stopping）。
- **混合方法**：报每参与者级数据 + 探针分 + 结构化/开放反思的质性归纳（CHI 重视）。
