> **背景一句话：** 「滑块好不好」是人群相对的——便利（写不出强 prompt 的人）vs. 有保证的增量控制（能写出强 prompt 的人）；average/best-prompt 两对照 = 这两类人真实备选的操作化。

## 决策 1 —— 「AI 熟练度」到底怎么定义和客观测量（人群划分）

- **问题：** owner 定了不让参与者自报「专家/普通人」，改以「是否 AI 熟练使用者」客观判定。那么这个熟练度用什么来量？
- **与论文耦合：** 论文里两人群是靠「**能不能自己写出强 prompt**」区分的（专家的真实备选=best-prompt，普通人=average-prompt）。study 的分层探针必须**操作化论文用的同一个 construct**，否则数据映射不回叙事。
- **选项：**
  - (a) **纯 prompt 能力探针**：给定目标，参与者自己写一条 prompt，按预注册 rubric 客观评分 / 或与 best-prompt 对齐度打分；接近 best 判为熟练。
  - (b) **复合**：探针 + AI 使用问卷（频率、是否用过参数/系统设置、是否理解 latent 控制）。
  - (c) **连续熟练度分**当调节变量（不硬切），10+10 只作两端锚点。
- **我的推荐默认：** (a) 作主判据（和两对照映射最干净）+ 记录使用频率当协变量。
- **需要写作 session 回答：** 论文对两人群的**精确定义**是什么？是纯「写 prompt 能力」，还是包含更广的 AI 熟练维度？（这决定探针只测写 prompt，还是要加问卷。）

---

## 决策 2 —— 「滑块是否赢过真实备选」用什么 quality 指标（最关键的耦合）

- **问题：** 增量控制轴要判「滑块产物 vs 参与者真实备选产物」谁更好。用**论文对象层的同一套判据**（目标属性上 δ=0.05 floor + CI 排零 + coherence 的门槛），还是用**面向用户的任务表现**指标？
- **与论文耦合：** 若用**同一对象层指标**，study 就是「把同一个对照约束门槛，换成真实用户自己的 prompt 当对照」——能和 0/12、PSR 那套模型证据直接对话、口径一致。若用**用户任务表现**，测的是实用/感知 benefit，但数值上和模型证据不平行。
- **选项：**
  - (a) **同对象层门槛/指标**，但对照换成：熟练层=参与者**自己写的 prompt**，非熟练层=average-prompt。
  - (b) **用户任务成功**指标（输出是否达成用户目标）。
  - (c) 两者都测。
- **我的推荐默认：** (a) 为主（保持与对照约束门槛、模型证据一致），(c) 若资源允许。
- **需要写作 session 回答：** ①确认对象层判据的确切形式；②在论文的对照框架里，把「参与者自己的 prompt」当作 comparator 的一个实例，是否可接受、怎么表述？

---

## 决策 3 —— average / best-prompt 两对照的定义是否与论文 Method 完全一致

- **问题：** study 的两对照臂是否**沿用论文 Method 里 best-prompt（frozen，已 🟢）和 average-prompt（🟡 pending）的同一操作化**（预注册候选池、DEV 选出等）？
- **与论文耦合：** study 说的「两人群真实备选」必须就是论文叫 average/best 的**同一对象**，否则两处对不上。
- **依赖警告：** average-prompt 臂在论文侧还是 🟡 pending；**Study B 的非熟练层对照悬在它上面**，它不定稿，B 无法最终定稿。
- **我的推荐默认：** 完全沿用论文定义；把 average-prompt 定稿列为 B 的前置依赖。
- **需要写作 session 回答：** average-prompt 的最终操作化是什么、预计何时定稿？

## 决策 4 —— Study B 在论文里的「身份/Claim 范围」

- **问题：** B 跑完后，允许进入 Contributions/Results 当**人群相对论点的证据**，还是严格停留在「Planned User Study」（point 7）+ 可应用性诊断（point 8）？
- **与论文耦合：** 决定设计要满足到什么严格度——confirmatory 证据要预注册 + MDE + 功效；planned 协议则现在不必上 MDE 招募。
- **选项：**
  - (a) **仅 planned/proposed**（本轮投稿不含数据）→ 现在只做协议草案，不冻结、不招募。
  - (b) **投稿前就跑并汇报** → 需完整协议冻结 + 伦理 + 功效计算。
- **我的推荐默认：** 取决于投稿时间线——见下。
- **需要写作 session / owner 回答：** **投稿 deadline 前会不会有 B 的数据？** 这直接决定现在是否要投入完整协议冻结与功效计算，还是先出 planned 协议占位。

## 决策 5 —— 「benefit 未测」caveat 的改写口径（论文侧要统一）

- **问题：** 采用 B 后，论文不能再写「benefit 未测」。统一改成什么？

## 决策 6 —— 偏 study 内部、耦合较低（我可给默认，但列出供参考）

- **对照臂 within vs between：** 每人都见 average+best（within，更省样本、可比）还是分组（between，避免学习/疲劳）。默认：within + 顺序抵消。
- **便利轴测量：** 客观（时间/步数/修改次数）+ 主观（简版 NASA-TLX / Likert）+ 备选偏好（用滑块 vs 自己写 prompt）。默认：三者都要。
- **是否嵌入 V3 门槛模块**当 point 8 诊断：默认嵌入（逻辑指纹不变、按引用），可让同一批人既做「可应用性」又做「评价」，一举两得。
- **这三条若写作 session 无异议，我按默认走，不再等。**
