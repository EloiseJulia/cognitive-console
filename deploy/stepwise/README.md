# Deploying the V11 stepwise study (public data collection)

> **状态提示 / STATUS**: This deployment collects **real human data**. Before
> recruiting, the research team must have closed the open human gates:
> ethics/informed consent, privacy & data-retention, and the protocol +
> preregistration freeze (frozen answer key, primary metric GAA, exclusion
> rules, sample size / MDE). Until those are frozen, collected data can only be
> treated as an exploratory pilot, **not** confirmatory paper evidence.

This directory deploys **only** the `button_board_stepwise` study to a free
Render web service backed by a free Render Postgres database.

## What changed vs. the loopback preview

The study logic, materials, expected answers, A/B design, sequences, and
GAA/Strict scoring are **unchanged** (logic fingerprint
`cb91ebcf…b0bd` preserved). Only transport/binding/storage and a front-end
consent gate were added:

- **Public mode** (opt-in via `STEPWISE_PUBLIC_ORIGIN`): binds a public
  address, validates CSRF/Host/Origin against the external origin, reads the
  verification key + admin token from the environment.
- **Persistence**: every signed export is written to Postgres on
  complete/save-exit, so a spun-down free instance never loses data.
- **Admin download**: `GET /admin/export?format=json|csv` guarded by
  `X-Admin-Token`. Participant entry stays fully public (no access code).
- **Consent gate**: the welcome screen shows a placeholder informed-consent
  block; the participant must tick “I agree” before **Begin** enables.
  **Replace the placeholder copy** in `static/study.js` (`CONSENT_COPY`) with
  the research team's approved bilingual consent text before recruiting.

## Environment variables

| Variable | Required | Notes |
|---|---|---|
| `STEPWISE_PUBLIC_ORIGIN` | yes | e.g. `https://stepwise-study.onrender.com` (no trailing slash). Enables public mode. |
| `STEPWISE_VERIFICATION_KEY` | yes | 64 hex chars (`openssl rand -hex 32`) or base64 ≥32 bytes. Keep it stable forever. Never commit it. |
| `STEPWISE_ADMIN_TOKEN` | yes | Owner-only token for `/admin/export`. Auto-generated by the blueprint. |
| `DATABASE_URL` | yes | Postgres connection string. **Required** in deployment mode: the server refuses to start without it so public data is never collected into volatile memory. The blueprint wires it from the Render Postgres database. |
| `PORT` | auto | Provided by Render; the server binds `0.0.0.0:$PORT`. |
| `STEPWISE_BIND_HOST` | no | Defaults to `0.0.0.0`. |
| `STEPWISE_MAX_SESSIONS` | no | Defaults to 500. |

## Deploy

1. Create a Render **Blueprint** pointing at `deploy/stepwise/render.yaml`.
2. Set `STEPWISE_PUBLIC_ORIGIN` to the service URL (after first deploy Render
   assigns `https://<name>.onrender.com`).
3. Set `STEPWISE_VERIFICATION_KEY` (`openssl rand -hex 32`).
4. Read the auto-generated `STEPWISE_ADMIN_TOKEN` from the dashboard.

## Download submissions

```bash
curl -H "X-Admin-Token: <token>" \
  "https://<origin>/admin/export?format=json" -o submissions.json
curl -H "X-Admin-Token: <token>" \
  "https://<origin>/admin/export?format=csv" -o submissions.csv
```

Exports are HMAC-signed and contain **no** expected answers or scoring keys.
Score them offline with the private materials via
`cognitive_console.button_board_stepwise.analysis`.

## Free-tier caveats

- Free web instances **sleep after ~15 min idle**; the first request after
  sleeping is slow. Persisted data survives sleep/restart (that is the point
  of Postgres); anything only in memory does not.
- Free Postgres has a limited lifetime/row budget — download data regularly.
- Fully public entry means random visitors can submit; rely on the attention
  check + exclusion rules to filter, and expect noise in the sample.
